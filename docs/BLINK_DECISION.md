# Is a machine-learning model necessary for the triple-blink trigger?

> Generated by `python -m bayn.events.blink_ml decide` on 2026-11-10 04:34. Re-run it after every new recording session; the criteria below are fixed in code (`bayn.events.blink_ml`: RECALL_MARGIN, FALSE_MARGIN, RECALL_TOLERANCE) and must not be changed to fit a result.

**Status: FINAL**

**Answer: No - the classifier is not clearly better than the simple rule on the learned blink signal, so the simpler rule is preferred.**

## The question

After the first real headset sessions showed that the blink detector had been looking at the wrong signal (the AF7/AF8 average; on the Muse, blinks are largest on TP9/TP10 because the reference sits on the forehead), the user asked (2026-11-10): *"now that the misconception has been cleared up, is a machine learning model even necessary?"* This test answers it with the person's own recordings.

## The test (pre-registered 2026-11-10, before the deciding sessions were recorded)

**Contenders.** Both are trained only on the sessions that are *not* being tested:
- **Rule**: count three blink peaks (0.2-0.8 s apart) on the person's *learned blink signal* (weights learned from their labelled blinks), with a threshold learned from the same sessions. Explainable, about a dozen numbers, could be set up by a short calibration.
- **ML**: a random-forest classifier on 31 EEG features of each candidate episode, trained on the person's real episodes plus synthetic ones recombined from their own blinks (synthetic data is used for training only).
- Reported for reference, not deciding: the rule on the old AF7/AF8 average (before), the rule plus a learned nod check (exploratory), and the classifier without synthetic data.

**Data and metric.** The person's real recording sessions, **leave one session out**: every session is scored by detectors that never saw it. A triple-blink prompt counts as caught if the detector fires within it; every other firing is a false trigger. Prompts are deliberately hard: double and four blinks, nods, head turns, looking around, talking.

**Decision rule.** The classifier counts as *necessary* only if it is **clearly** better than the rule:
- it catches at least **10 points more** triple blinks with no more false triggers, **or**
- it makes at least **0.5 fewer false triggers per minute** while catching at most **5 points fewer**.
- Otherwise the simpler rule wins. The live system's *Auto* setting applies the same rule.

**Final** once the data includes a boundaries, a noisy, a standard session, and sessions done seated and standing (user, 2026-11-10: the demo may be given standing). Walking in place (spoken prompts) is reported per condition but not required. A badly recorded session may be deleted and re-recorded (dashboard: Train… → Saved sessions) - before running this test, never because of its result.

## Verdict

- Recall: ML 64 % vs rule 67 % (needs +10 points).
- False triggers: ML 0.73/min vs rule 0.3/min (needs 0.5/min fewer).
- **No - the classifier is not clearly better than the simple rule on the learned blink signal, so the simpler rule is preferred.**

## Limits

- One person, one headset, one fit per session. A different wearer needs their own sessions.
- The prompts are adversarial on purpose; in normal use, triple-blink look-alikes are rarer. The 10-minute normal-activity test (TESTING.md, Phase 6) measures that separately.
- With ~30 prompts per variant, differences of a few prompts are within the confidence intervals; the margins above exist so that noise can't decide.
